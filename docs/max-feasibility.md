# S-11 MAX 적용 가능성·후속 구현 기준

2026-11-15 KST · [#12](https://github.com/we-self-sufficiency/parksical-server/issues/12) · F-08/F-10/F-11/F-16. 근거 ID P1~P7/V1~V10/A1과 버전·확인일은 [차량 계약 근거](vehicle-contract-notes.md)에 기록했다. 아래는 **가역적인 개발 제안 A-14**이며 사용자/플랫폼/장소 운영자의 승인이나 실차 검증 결과가 아니다.

## 결론과 현재 준비 상태

일반 주차 기능을 먼저 진행하고 MAX는 합성 환경에서 룰·결과 정합성을 개발하는 방향을 권장한다. 다섯 후보 모두 실차 운영 활성화는 막혀 있다. 조향각·브레이크 등의 문서상 경로가 존재해도 현재 앱/차량에서 필요한 품질과 권한이 확인된 미션은 없다.

P2는 게임 기능의 주행 중 사용을 제한한다. 따라서 “작은 HUD”, 화면을 숨긴 백그라운드 판정, 모빌리티 분류 또는 폐쇄 주차장이라는 이유만으로 게임 미션을 허용할 수 없다. P1의 주차 모빌리티 예시는 MAX 게임까지 허가한 근거가 아니다. 구체적 서비스 분류/백그라운드 처리 가능 범위는 D-04의 외부 답변 대상으로 남긴다. 권장 제한 로직은 앱이 로컬에서 수행하며 서버 지연/단절 때문에 우회되지 않아야 한다.

이 조사를 반영한 PR #31은 문서만 변경했고 당시 OpenAPI0.9.0/49연산에 새 MAX API를 추가하지 않았다. 후속 **S-12 합성 미션/도전·최종 결과5연산**의 개발 계약·설정·DB·오류/재시도·OpenAPI0.10.0은 [미션 가이드](missions.md)를 따른다. 실차 미션 지원/운영 게임 허용을 확인한 것은 아니며 아래 D-02/D-04와 E1~E8 조건은 유지한다. 리포트·예약·랭킹은 계속 후속이고 S-10 QR의 D-07도 미정이다.

## 미션별 지원 판정

`문서 경로 확인`은 실차 지원 확정이 아니다. `미확인`은 미지원과 다르며 해당 장치의 capability/권한/관측 품질을 받으면 갱신한다. 현재 **실차 지원 확인 0개**, **실차 미확인 5개**다. 특정 후보 전체가 플랫폼에서 영구 미지원이라고 단정하지 않는다. 제거가 명시된 기존 VehicleSpeedListener만 V2 버전에 대해 미지원으로 구분한다.

브레이크와 일반 경고등은 의미를 확인했을 때 보조 중단 조건으로 쓸 후보이며 필수 신호 누락을 메우지 않는다. 지원이 없는 미션을 정상처럼 보여주지 않는다. 일반 위치 메모·수동 주차장 선택은 별도 기능으로 남길 수 있으나 MAX 성공/랭킹 자격으로 승격하지 않는다.

## 구간·종료·중단 제안

### 시작과 구간

시도는 사용자/설치 연결·미션/룰 version·lot/구조 version·승인된 경로/구간·운영 시간에 고정하는 후보로 한다. 현재 합성 주차장의 도전 허용은 계속 false다. 가상 WGS84 (0,0)·평면도·내비 목적지·별점·예약 성공을 실차 자격 증명으로 쓰지 않는다.

ARMED는 대기, RUNNING은 유효한 진입 관측 뒤의 판정 구간을 의미하는 **앱 논리 상태 제안**이다. 시작 전에는 정책 허용·유효 시간/장소·동의·지원/권한·필수 신호 신선도·사용자 연결을 모두 만족해야 한다. 하나라도 알 수 없으면 시작하지 않는다. 새 서버 상태 enum으로 확정한 것은 아니다.

진입/출구는 구조 버전에 연결된 경계와 앱 관측 근거가 함께 필요하다. 수동 시작 버튼은 의도만 표현한다. 지하 위치·구간 근거가 부족하면 미확정이며 핸들 360도 누적이나 내비 도착으로 추정 공백을 채우지 않는다. 구간 중 구조/룰/사용자 연결이 바뀌면 기존 시도를 무효 종료하고 새 시도로만 재개한다.

|---|---|---|

정지 허용 오차·관측 확인 기간·신호별 최대 공백·최소 표본·시간원/리부트 처리는 E2/E4/E6 증거를 받아 룰 version에 고정한다. SDK가 보장하지 않은 Hz나 공통 stale 초를 이번 조사에서 만들지 않는다. 종료는 논리적으로 한 번이며 중단/판정 불가는 무보상이다. 앱 재시작/승인되지 않은 백그라운드 전환은 판정 불가로 닫고 자동 재개하지 않는 보수적 제안이다. 서버 통신 단절 자체와 로컬 신호 단절은 구분하되, 오프라인 시에도 로컬 정책/종료 처리는 지속 적용한다.

### 10km/h·1초와 경고 2회/3초 충돌

| 원 기획 | 권장 정리 A-14 | 남은 확인 |
|---|---|---|
| 10km/h 초과 1초 vs 즉시 중단 | **유효한 관측에서 절대 차속 >10km/h를 확인하는 즉시 판정 중단**. 1초는 선택적 사후 지속성 분석에만 쓰고 중단 대기 시간으로 사용하지 않음. 정확히10은 이 개발 비교식의 초과가 아님 | 10은 원 기획 후보값이며 안전 속도 인증/운영 승인 아님. 목표 환경의 한계는 D-04와 실차 품질 확인 후 고정. UX/위험 중단은 속도와 별개로 우선 |
| 3초 내 경고 2회 | 실제 의미가 확인된 위험 이벤트는 첫 유효 이벤트에서 즉시 판정 중단하는 제안. 2회/3초는 이벤트 동일성·종류·중복을 검증한 후 사후 분석 후보로만 분리 | Telltales on/blink/재통지를 별개 위험으로 세지 않음. 주차 경고를 확인하지 못하면 해당 지표는 미확인. 세부 위험 분류/단위/ID·시간원은 E5 필요 |

“즉시”는 앱이 유효 이벤트를 관측한 시점의 판정 종료이지 센서 무지연·충돌 예방 보장이나 차량 제동 명령이 아니다. 이 서버는 차량을 정지시키거나 브레이크/조향을 제어하지 않는다. 무효한 차속/공백을 “한계 미만”으로 판정하지 않는다.

## 점수·장소·개인정보와 서버 검증 경계

빠른 완료/높은 속도/정지 회피에 보너스를 주지 않는다. 통제된 유효 구간의 규칙 준수와 품질을 평가할 후보이며 타임아웃은 재촉 UI 없이 시도를 종료하는 상한일 뿐이다. 정지·취소·안전 개입으로 점수를 잃거나 연속 성공 기록을 회복하려고 위험 운전을 유도하지 않도록 #13/#14에서 실패/중단/판정 불가를 분리한다.

운영은 다음 **전부**를 필요로 한다. 플랫폼의 실제 기능 분류/주행 동작 허용 답변, 명시적 장소 운영자 허가·경로/시간/수용량/차량 조건, 대상 차량의 신호/품질/UX 검증, D-02 동의/최소 보관/철회·삭제, 기록 인정·공개/보상 정책. 폐쇄 공간·주차장 소유·낮은 속도만으로 플랫폼 예외나 법적 허가가 생겼다고 보지 않는다. 별점·기계식 주차장·예약 결제를 도전 허가로 대체하지 않는다.

| 영역 | 서버가 원본 없이 검사할 수 있는 것 | 증명할 수 없는 것 |
|---|---|---|
| 자격/범위 | 인증 주체/설치 연결, 허용된 룰·구조·기간·미션 조합, 동의/예약/상태 | 해당 차량이 현장에 있었거나 실제 SDK를 사용했는지 |

#13 결과 DTO는 위 최소 메타데이터·품질·중단 사유·단위/버전·시도 ID와 산출 요약을 구체화하는 작업이다. 이번 표는 신규 요청 스키마가 아니다. 원본 차속/조향/기어 시계열을 범용 payload나 capability 이벤트에 끼워 넣지 않는다. 실제 계정 연결 운전 결과/위치는 D-02 전 수집하지 않고 최소 요약의 보관/삭제도 결정 대상으로 남긴다. 품질·원천 진위가 검증되지 않은 결과는 실제 랭킹·쿠폰으로 연결하지 않는다.

## 통합과 SDK 공유

이 PR의 문서 링크/계약 검사를 수행하고 기존 CI를 확인한다. 운영 배포·SDK 연결/실차·앱 심사·외부 답변은 검증하지 않았다. develop 병합 뒤 Wiki Home에 #12/머지 PR/날짜를 기록하고 MAX 조사 가이드를 연결한다. 새 API가 없고 후속 구현의 준비 조건만 바뀐다는 점, D-02/04와 E1~E8 미확인, 다음 #13 합성 범위를 함께 공유한다.


### S-12/S-13 후속 구현 참고

위 문서는 S-11 조사 당시 범위다. 이후 [S-12 미션·불변 결과](missions.md)와 [S-13 연습 리포트·합성 자격](practice.md)를 비운영 SYNTHETIC 범위로 구현했다. S-13은 OpenAPI0.11.0/연습5연산과 practice-v1의 발생 순서·무효/지연 재계산을 제공한다. D-02/D-04·앱 E1~E8은 계속 미완료이며 실차 지원/운영 승인으로 해석하지 않는다. 각 통합/검증·Wiki 상태는 해당 PR/이슈를 확인한다.

[S-14 합성 예약](reservations.md)은 비운영 명시 정책/30분 슬롯·서버 견적·임시 점유/만료·취소·샌드박스 전이를 구현했다. 실제 제공자/청구·운영 장소 확정은 없고 D-04/D-05를 미완료로 유지한다. 예약을 실제 정차/주행 허가/미션 자격으로 승격하지 않는다. 통합/CI·Wiki 상태는 #15/PR을 따른다.
